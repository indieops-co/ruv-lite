# Compare: the scorecard shape

For "X vs Y", where one side is what the user has (or the conventional choice) and the other is a rUv
technology.

**What you're choosing between.** One line each: what the conventional option is, what the rUv option is,
in plain words.

**The scorecard.** Score each row from where the user stands, not in the abstract. A cell is a few words,
never a paragraph. Mark the better side of each row with `◀` or `▶`, or `=` when it's a wash.

| Dimension | <Conventional> | | <rUv option> |
|---|---|:-:|---|
| Complexity | | | |
| Maturity | | | |
| Performance | | | |
| Cost | | | |
| Local / privacy | | | |
| Scale | | | |
| Learning burden | | | |
| Reversibility | | | |
| Strategic upside | | | |

Rules for the cells:

- **Performance** and **Cost**: a benchmark the project publishes is a *claim*. Write "claimed faster at
  X (vendor benchmark)" and never put the number in the conventional column's terms.
- **Maturity**: the version, and the experimental / alpha / pre-1.0 label if there is one.
- **Strategic upside**: what becomes possible later, stated once. It can't outweigh a present cost on its own.

**What decides it.** Two or three sentences: which rows matter for *this* user, and why they outweigh the
rest. More rows won by one side doesn't mean that side wins.

Then THE CALL (`call-card.md`).
