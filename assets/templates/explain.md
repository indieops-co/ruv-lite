# Explain: the seven-part shape

Plain English for someone who has never used the technology. Every section is one to three sentences. No
acronym or jargon word appears without its glossary meaning beside it.

**<Name>**: <one sentence: what it is, as you'd say it to a smart friend who doesn't code much>.

1. **What it is.** The plain description, from the card's `In plain words`. Add the status if it's
   experimental, alpha or pre-1.0.
2. **What problem it solves.** The pain someone has before they reach for it.
3. **What you probably already use instead.** The conventional tools for the same job.
4. **When it becomes interesting.** Concrete situations where it beats those tools.
5. **When you don't need it.** Concrete situations where it doesn't, which is most projects.
6. **Difficulty.** The budget level of the lightest real path (Low / Medium / High / Very high), and what
   that means here: "Medium: a new package and a small adapter in your code."
7. **Try it without committing.** The lightest path from the card: a project-scope plugin, a sandbox folder,
   a docs quickstart. Say what it touches and how to undo it. Don't run it.

**Sources:** the card's canonical links, one line. Add the snapshot date, or "checked live" if you checked.
